# CLAUDE.md — инструкции для агента (КОМПАС · голосовые практики)

## Что это
Отдельный B2C-продукт: мобильное приложение голосовых практик — **навигатор
состояний**, а не библиотека медитаций. Android-first (Kotlin + Jetpack Compose),
тёмная тема. **Не путать** с сервисом для психологов `cmpas.ru` — это другой
продукт, другая аудитория, другой репозиторий.

## Перед началом работы — обязательно прочитай
1. `design_handoff_kompas_mvp/README.md` — ТЗ Claude Design (источник истины по дизайну)
2. `docs/PRODUCT.md` — логика экранов, флоу, edge-cases, тон микрокопи
3. `docs/PRIVACY-DPO.md` — данные, разрешения, 152-ФЗ
4. `docs/QA-TESTPLAN.md` — критерии приёмки, анти-паттерны, DoD
5. `docs/ROADMAP.md` — что сделано и что дальше

## Продуктовые принципы (не нарушать)
- **≤2 тапа до звука.** Всё подчинено этому.
- **Тёмная тема — единственная** в MVP. Акцент действий — **только terracotta** `#C98A6B`.
- **Разрешающий тон** микрокопи: «можно», «если будет удобно», «необязательно
  сейчас». Никогда — «вы должны», «не сдавайтесь», «вернитесь», «вы пропустили».
- **Приватность по умолчанию:** данные локальны, без бэкенда и аккаунтов в MVP.
- **Никаких медицинских/целительских заявлений** (и продукт, и модерация сторов).
- **Анти-паттерны запрещены:** стрики, серии, бейджи, уровни, конфетти, рейтинги
  звёздами, соцфункции, автоплей следующего трека, тревожные пуши, обратный
  отсчёт/тёмные паттерны в пейволле.

## Дизайн (не менять без явного запроса пользователя)
- Палитра/типографика/отступы — из `docs/DESIGN-SYSTEM.md` и хэндоффа.
- Дышащий фон — ключевая анимация (цикл 10с: 4с расширение / 6с сжатие).

## Стек
Kotlin 2.1 · Jetpack Compose (Material 3) · DataStore (локальные данные) ·
Media3/ExoPlayer (звук — на этапе интеграции аудио) · Navigation через простой
стейт-роутер. minSdk 26, targetSdk 35. Без Hilt (service-locator `AppContainer`).

## Сборка и деплой
- CI: `.github/workflows/android-build.yml` собирает **release**-APK (minify +
  shrink), подписывает рабочим ключом из секретов CI и публикует релиз. Отладочный
  (debuggable) пакет людям не раздаётся — он вычитывается отладчиком и не проходит
  Google Play; сторож CI роняет сборку на debuggable-пакете.
- **Ключ подписи — в секретах CI, не в репозитории** (`ANDROID_KEYSTORE_BASE64` +
  пароли; отпечаток закоммичен в `android/app/EXPECTED_SIGNER.txt` и сверяется со
  собранным APK). Ключ менять нельзя — иначе обновление поверх установленных копий
  сломается.
- Разрешения — единственный источник истины `android/app/android-permissions.txt`;
  CI сверяет с ним `aapt2 dump permissions` готового APK.
- Локально: `cd android && gradle assembleRelease` (выйдет неподписанным — подпись
  на стороне CI) или `assembleDebug` для отладки.

## Правило именования сборок (СИМПАС — общее для трёх продуктов)
Едино для praktika · zapiski · momenty. Продукт этого репозитория — **momenty**.
- Имя файла: `simpas-<продукт>-<версия>.apk` → напр. `simpas-momenty-0.1.1.apk`
- Тег релиза: `<продукт>-v<версия>` → напр. `momenty-v0.1.1`
- Постоянная ссылка: `https://cmpas.ru/updates/latest/momenty.apk`

Правила: приставка **simpas** — по имени системы из трёх продуктов, не по имени
одного (`kompas`/`compas`/`cmpas` — три разные транслитерации КОМПАСА, в артефактах
их не используем). Латиница строчная, **без хеша коммита и без номера прогона** —
человек видит имя в загрузках, суффикс `-b27`/`-a3f9c21` ему ничего не сообщает.
Релиз соответствует **версии, а не прогону**: пересобрали ту же версию — обновляем
существующий релиз и его файл, новый не создаём. `versionCode`/`versionName` при
правках сборки/подписи/разрешений/имён **не трогаем** — это исправление доставки,
не новая версия. `applicationId` (`ru.cmpas.voice`) и ключ подписи неизменны, иначе
для системы это другое приложение и обновление поверх ломается.
Правило застраховано сборкой: шаг «Имя артефакта и тег» в CI роняет сборку, если
имя файла или тег не соответствуют шаблону.
