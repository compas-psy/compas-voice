# КОМПАС · Голосовые практики — продуктовая логика (CPO)

> Источник истины по дизайну — `design_handoff_kompas_mvp/README.md` (ТЗ Claude Design)
> и HTML-прототип. Этот документ **не переопределяет** дизайн, а достраивает
> **поведение**: что происходит на каждый тап, какие состояния возможны, где
> граничные случаи, и как они разрешаются. Разработка ведётся строго по нему.

## 0. Суть продукта (одним абзацем)

Это **не библиотека медитаций, а навигатор состояний**. Пользователь приходит
не «помедитировать», а **выйти из конкретного состояния**: не может уснуть,
не может выключить работу, тревожно, потерял опору. Ядро — глубокий мужской
голос и точные сценарии переходов. Главный KPI взаимодействия: **от открытия
до звука голоса — не более двух тапов.** Всё остальное подчинено этому.

Аудитория: городские люди 25–45, уставшие, без медитационного опыта и интереса
к эзотерике. Слушают вечером и ночью, лёжа, в темноте, одной рукой, иногда в
моменте тревоги. Отсюда — минимум решений на экране, тёмная тема, разрешающий
тон, никакой геймификации.

## 1. Карта состояний приложения (высокоуровневый флоу)

```
[Холодный старт]
      │
      ▼
 onboardingCompleted? ──нет──► Онбординг 2a → 2b → 2c(выбор состояния) ──► [Дом]
      │да
      ▼
   [Дом «Сейчас»]  ◄──────────────────────────────────────────┐
      │ (тап по плитке состояния)                              │
      ▼                                                        │
   [Шит перед стартом]  (длительность · фон · чек-ин «до»)     │
      │ «Начать»                                               │
      ▼                                                        │
   [Плеер]  играет ⇄ пауза ⇄ (ночной / угасание)               │
      │                                                        │
      ├─ сонная практика ──► [Сонное угасание] ──► тихо в Дом ──┤
      │                                                        │
      └─ обычная практика ─► [После практики «Как сейчас?»] ────┤
                                    │ «Готово»                  │
                                    ▼                           │
                        первая практика завершена? ──да──►[Пейволл]──(закрыл)─┘
```

Табы (нижний бар, 3 вкладки): **Сейчас** · **Практики** · **Я**.
Онбординг, шит, плеер, пейволл, экран «после практики» — **вне таб-бара**
(модально/полноэкранно).

## 2. Онбординг (2a → 2b → 2c) — показывается один раз

**Цель:** снять недоверие («это не эзотерика») и мягко ввести. Не собирать
данные, не просить регистрацию, не просить разрешений.

| Экран | Что делает | Кнопка | Поведение |
|---|---|---|---|
| 2a «Что это» | Логотип, крупный заголовок, подпись, индикатор 3 точки | «Далее» (нейтральная) | → 2b. Свайп влево тоже листает. |
| 2b «Честность» | «Без обещаний исцеления…» | «Далее» | → 2c |
| 2c «С чего начнём?» | Radio-выбор из 4 состояний | «Начать» (terracotta) | Сохраняет `selectedState`, ставит `onboardingCompleted=true`, → Дом. |

**Логика поведения:**
- Индикатор точек: активная — terracotta, шире (22px). Синхронизирован со свайпом.
- Кнопка «Далее» на 2a/2b всегда активна. На 2c «Начать» активна **всегда**
  (по умолчанию предвыбрано первое состояние «Не могу уснуть»), чтобы не
  создавать «стену» — выбор можно поменять, но нельзя застрять.
- **Назад:** системная кнопка «назад» на 2b/2c возвращает на предыдущий экран;
  на 2a — сворачивает приложение (не выходит в пустоту).
- `selectedState` из онбординга влияет только на **первый** показ Дома
  (подсвечивает соответствующую плитку мягким акцентом). Дальше поведение Дома
  определяется временем суток. Это «мостик», а не жёсткая настройка.
- **Пропустить онбординг нельзя** (всего 3 экрана, но третий = полезный выбор).
  Это не «стена» в понимании анти-паттернов: экранов мало и они несут смысл.

**Edge-cases:**
- Убил приложение на 2b → при перезапуске онбординг начинается с 2a заново
  (`onboardingCompleted` ставится только на «Начать»). Промежуточный прогресс
  не сохраняем — так проще и честнее.
- Смена языка системы: тексты онбординга берём из ресурсов (ру-первый MVP).

## 3. Дом «Сейчас» (таб 1) — три темы по времени суток

Открывается на вопросе **«Что сейчас?»**. Набор плиток и тема выбираются
**по системным часам устройства** (без бэкенда):

- **День** (≈ 05:00–17:59): фон `#14171F`, сетка 2×2, eyebrow «<день недели> · день».
- **Вечер** (≈ 18:00–22:59): фон `#14171F`, 2×2 + широкая плитка «Трудный разговор».
- **Ночь** (≈ 23:00–04:59): фон `#0A0C10` (темнее), заголовок «Не спится?»,
  3 крупные плитки в столбик, приглушённая яркость и terracotta.

**Логика поведения:**
- Тайм-бакеты — **границы задаём константами** (`TimeOfDay.of(hour)`), чтобы
  QA легко проверял и чтобы позже вынести в настройку. Пересчёт — при каждом
  входе на таб и при `onResume` (пользователь мог продержать приложение
  открытым до полуночи).
- Один тап по плитке → **шит перед стартом** для соответствующей практики.
  Плитка состояния маппится на конкретную практику каталога (маппинг ниже §9).
- Плитки — **48pt+**, вся плитка кликабельна, лёгкий haptic + press-scale 0.975.
- Логотип (38px) — **не кликабелен** (это не кнопка, чтобы не плодить решения).
- Eyebrow с днём недели/временем — информативный, не интерактивный.
- Ночь: статус-бар приглушён, автопонижение яркости **не** трогаем на Доме
  (только в плеере ночных практик — см. §6). Дом ночью просто визуально темнее.

**Edge-cases:**
- Ровно 23:00 → ночь; ровно 05:00 → день (границы включаем в «светлую» сторону
  однозначно, документируем в коде).
- Часовой пояс/перевод часов: используем локальное время устройства; ручных
  пересчётов не делаем.
- Нет практики под плитку (теоретически) → плитка неактивна с подписью, но в
  MVP все 4/5 плиток каждого времени суток замаплены на реальные практики.

## 4. Каталог «Практики» (таб 2)

Large Title «Практики». Практики карточками, **сгруппированы по состояниям**:
Сон · Выход из дня · Тревога и перегрузка · Разговоры и решения · Опора.
Заголовок группы + счётчик («3 практики»). **Поиска нет** (каталог мал: 8–12).

**Логика поведения:**
- Тап по карточке → шит перед стартом.
- Чипы длительностей (5/12/20) на карточке — **информативные**, не выбор:
  выбор длительности делается в шите. (Показывают, какие длительности есть.)
- Карточка: свой градиентный фон по состоянию + «дышащее» пятно.
- Прокрутка вертикальная, группы идут секциями. Верхняя safe-area + Large Title
  сжимается при скролле (нативное поведение).

**Edge-cases:**
- Практика недоступна без подписки (после пейволла) → карточка помечается
  мягким замком; тап открывает пейволл, а не шит. В MVP до первого пейволла
  всё открыто; после — часть каталога за подпиской (см. §8, `subscriptionStatus`).

## 5. Шит перед стартом (bottom sheet) — точка сбора решения

Нативный bottom sheet поверх Дома/Каталога. Содержит: eyebrow группы + название
практики · **Длительность** (сегмент 5/12/20) · **Фон** (сегмент «Только голос»/
«Мягкий фон») · **Мягкий чек-ин** слайдер «Насколько сейчас напряжённо?» 0–10 ·
кнопка **«Начать»** (terracotta) · ссылка **«Пропустить чек-ин»**.

**Логика поведения:**
- Значения по умолчанию: длительность — **12** (середина); фон — из
  `settings.defaultBackground` (по умолчанию «Только голос»); чек-ин — **не
  трогается пользователем = не записан** (слайдер стоит на 5, но пока не
  двигали — считаем «пропущен», если только не нажали именно на трек).
  Решение: считаем чек-ин заполненным, если пользователь **коснулся слайдера**
  ИЛИ нажал «Начать» после явного взаимодействия. Проще и честнее: слайдер
  по умолчанию на 5, и мы записываем значение, только если было касание;
  «Пропустить чек-ин» и «Начать без касания» → `checkInBefore = null`.
- «Начать»: haptic, собирает `sessionConfig {duration, background}` +
  `checkInBefore`, открывает **плеер**, стартует аудио. Это тап №2 (плитка →
  «Начать»). Требование «≤2 тапа до звука» выполнено.
- «Пропустить чек-ин»: `checkInBefore = null`, сразу можно жать «Начать»
  (или можно объединить — «Пропустить» стартует практику без чек-ина). В MVP:
  «Пропустить чек-ин» **скрывает слайдер** и оставляет только «Начать».
- Свайп вниз/тап по подложке — закрывает шит без старта (возврат на Дом/Каталог).
- Слайдер: заливка градиент smoky→terracotta, бабл со значением, подписи
  «0 · спокойно» / «10 · на пределе». Шаг 1. Тач-цель ручки 48pt.

**Edge-cases:**
- Открыл шит, свернул приложение, вернулся → шит сохраняет выбранные значения
  (состояние во ViewModel/rememberSaveable).
- Двойной тап по «Начать» → защита от повторного старта (флаг `isStarting`).

## 6. Плеер — самый важный экран

Почти пустой. Дышащий фон (цикл 10с: 4с расширение / 6с сжатие). Крупная зона
пауза/плей по центру. **Тап по всему экрану = пауза/плей.** Контролы: «−15 сек»,
«Таймер сна», «Фон». Прогресс — тонкая линия 2px + мелкие тайминги.

**4 состояния:**
1. **Играет** — 2 пульсирующих кольца вокруг стеклянного круга (2 палочки паузы),
   подсказка «Нажми в любом месте, чтобы поставить на паузу».
2. **Пауза** — дышащие пятна остановлены, треугольник плей, подсказка «На паузе».
3. **Ночной режим** (сонные практики) — яркость экрана вниз, минимум хрома,
   одно тонкое кольцо, «Таймер сна · N мин».
4. **Сонное угасание** — у сонных практик **нет финального экрана**: UI плавно
   гаснет к концу трека, звук затухает, сессия завершается тихо.

**Логика поведения (детально):**
- **Тап по экрану** переключает play/pause. Контролы («−15», «Таймер», «Фон») —
  отдельные тач-цели, тап по ним **не** ставит на паузу (останавливаем всплытие).
- **«−15 сек»** — перемотка назад на 15с (не меньше 0). Никакой перемотки вперёд
  (продукт про «побыть», а не «пролистать»). Haptic лёгкий.
- **«Таймер сна»** — открывает выбор длительности сна (напр. 10/20/30/45 мин
  или «до конца трека»). По истечении — плавное затухание звука за ~20с и стоп,
  экран гаснет (как §4c). Таймер сна **переживает** блокировку экрана.
- **«Фон»** — переключает «Только голос» ⇄ «Мягкий фон» на лету (кроссфейд
  амбиента). Не прерывает голос.
- **Прогресс** — по позиции трека; тайминги «прошло / осталось». Перемотки
  тапом по прогрессу нет (линия декоративная + информативная; чтобы не
  промахиваться в темноте).
- **Крестик (закрыть)** — останавливает практику, спрашивает подтверждение?
  Нет — закрытие тихое, но: если практика **не сонная** и прослушано >30с —
  ведём на экран «После практики». Если прослушано <30с — просто закрываем
  (не мучаем чек-ином за незавершённое). Сонные — всегда тихо в Дом.
- **Ночной режим** включается автоматически, если практика из группы «Сон»
  ИЛИ системное время ночное. Понижаем `screenBrightness` окна плавно, сохраняя
  исходное значение; **восстанавливаем при выходе** (в т.ч. при сворачивании).
- **Аудиофокус:** запрос audio focus; на входящий звонок/другой плеер — пауза;
  по возвращении фокуса — **не** автовозобновляем (пользователь сам решит; но
  для сонных — можно тихо продолжить; MVP: пауза везде, ручное возобновление).
- **Наушники выдернули** (ACTION_AUDIO_BECOMING_NOISY) → пауза.
- **Фоновое воспроизведение:** практика продолжает играть при выключенном
  экране/сворачивании (MediaSession + foreground service). Уведомление-плеер
  минимальное: название, пауза/плей, закрыть. Без навязчивости.

**Edge-cases:**
- Трек не загрузился/битый URL → мягкий не-алармовый экран «Не получилось
  включить. Попробуй ещё раз» + кнопка «Повторить», без красных ошибок.
- Звонок во время сонного угасания → пауза; при возврате остаёмся на паузе,
  экран не «вспыхивает» яркостью резко (плавно).
- Таймер сна + конец трека раньше таймера → трек закончился, затухание по треку.
- Пользователь свернул на паузе на час → при возврате состояние сохранено.

## 7. После практики «Как сейчас?» (не для сонных) — 5a

Повтор слайдера 0–10 (чек-ин «после»). **Тихое сравнение «было 7 → стало 4»**
в карточке (стрелка terracotta, подпись «чуть отпустило») — без похвал/конфетти.
Кнопка **«Готово»** возвращает на Дом. **Никакого автопредложения** следующей
практики.

**Логика поведения:**
- Показывается только если: практика **не** сонная И была осмысленно
  прослушана (>30с или доиграла).
- Сравнение «было→стало» показываем, **только если** был чек-ин «до»
  (`checkInBefore != null`). Иначе — просто «Как сейчас?» со слайдером, без
  сравнения (не выдумываем «было»).
- Подпись динамики зависит от дельты:
  - стало заметно ниже (Δ ≤ −2): «чуть отпустило» / «стало спокойнее»;
  - примерно так же (|Δ| ≤ 1): «побыл(а) с этим» (нейтрально, без осуждения);
  - стало выше (Δ ≥ 2): «бывает и так — это нормально» (никогда не «вы сделали
    хуже»). **Разрешающий тон в любом исходе.**
- «Готово» пишет `checkInAfter` в `history`, закрывает экран → Дом.
- «Пропустить» (мелкая ссылка) — тоже закрывает, без записи «после».

**Edge-cases:**
- Не двигал слайдер «после» → считаем пропущенным (не записываем 5 по умолчанию).
- Практика доиграла в фоне (экран заблокирован) → при разблокировке показываем
  этот экран (или уведомление «практика завершена», тап → этот экран).

## 8. Пейволл — 6b

Показывается **после первой полностью прослушанной бесплатной практики**
(триггер `hasCompletedFirstPractice`). Мягкий: «Первая практика — за нами.» +
3 преимущества с галочками; кнопка «Попробовать 7 дней бесплатно»; честная
подпись «Потом 399 ₽ в месяц. Отменить можно в любой момент.»; ссылка «Пока
не сейчас». **Никаких таймеров обратного отсчёта.**

**Логика поведения:**
- Триггер — ровно один раз, при первом `checkInAfter`/завершении (для сонных —
  при завершении трека). Флаг `hasSeenPaywall` не показывать повторно навязчиво.
- «Пока не сейчас» → закрывает, `subscriptionStatus` остаётся `free`.
  В MVP без реального биллинга: подписку **эмулируем локально** (см. DPO/roadmap)
  или ведём на системный биллинг позже. MVP-задача — показать экран и не
  давить. Кнопка «Попробовать» в первой версии может ставить `trial` локально
  или открывать заглушку «Скоро». Финальный биллинг — Google Play Billing
  (Горизонт следующий).
- После пейволла часть каталога может стать «за подпиской» — но в MVP разумнее
  оставить весь каталог открытым и не блокировать (чтобы не ломать доверие на
  старте). Флаг блокировки каталога — под фиче-флагом, по умолчанию OFF.

**Анти-тёмные-паттерны (жёстко):** нет обратного отсчёта, нет предвыбранной
галочки «согласен на списание», цена видна сразу и честно, «Пока не сейчас»
не спрятана и не серым-по-серому.

## 9. Профиль «Я» (таб 3) — 6a

Large Title «Я». Спокойный список без графиков-достижений:
- **Мягкая тенденция** (не дашборд): текст «За последние две недели напряжение
  перед практикой в среднем чуть ниже.» + тонкий sparkline (одна линия
  terracotta, без осей/сетки).
- **Недавнее** — список прослушиваний: название + «вчера · 12 мин»; у части —
  тихая динамика «7 → 4».
- **Настройки:** «Фон по умолчанию › Только голос»; «Напоминания» — тумблер
  **по умолчанию ВЫКЛ**, подпись «Могу напомнить вечером. Если будет удобно.»;
  «Подписка › Бесплатный доступ».

**Логика поведения:**
- Тенденция считается из локального `history` по `checkInBefore`. Показываем
  текст, **только если** данных достаточно (≥3 практики с чек-ином за 14 дней),
  иначе — мягкая заглушка «Здесь появится спокойная сводка, когда наберётся
  немного практик.» Никогда не выдумываем тренд из 1 точки.
- Формулировка тенденции адаптивна к знаку: «чуть ниже» / «примерно так же» /
  «чуть выше» — всегда без оценки.
- «Недавнее»: последние N (напр. 20) практик, дата в человеческом виде
  («сегодня/вчера/N дней назад»). Тап по строке — можно повторно открыть шит
  той же практики (удобно вернуться к тому, что помогло). В MVP — необязательно,
  можно сделать некликабельным списком.
- «Напоминания»: тумблер ON запрашивает разрешение POST_NOTIFICATIONS
  (Android 13+). Одно вечернее напоминание, время по умолчанию 21:00, можно
  выключить в любой момент. **Никаких тревожных пушей**, текст разрешающий.
  Выкл по умолчанию — сознательно.
- «Фон по умолчанию» — открывает выбор «Только голос»/«Мягкий фон», пишет
  `settings.defaultBackground`.
- «Подписка» — открывает пейволл/экран статуса подписки.

## 10. Маппинг «плитка состояния → практика каталога»

Каждая плитка Дома ведёт к конкретной практике. Каталог из 8–12 практик по
группам. Пример маппинга (финальные названия — из HTML-прототипа/аудио-пакета):

| Время | Плитка | Группа | Практика (пример) |
|---|---|---|---|
| День | Перегружен(а) | Тревога и перегрузка | «Сбросить обороты» |
| День | Не знаю, за что взяться | Опора | «Вернуть опору» |
| День | Трудный разговор | Разговоры и решения | «Перед разговором» |
| День | Потерял опору | Опора | «Найти землю под ногами» |
| Вечер | Работа не отпускает | Выход из дня | «Ночь без внутренних совещаний» |
| Вечер | Прокручиваю мысли | Тревога и перегрузка | «Остановить карусель мыслей» |
| Вечер | Не могу уснуть | Сон | «Медленное погружение» |
| Ночь | Не могу уснуть | Сон | «Медленное погружение» |
| Ночь | Проснулся среди ночи | Сон | «Вернуться в сон» |
| Ночь | Тревожно в темноте | Тревога и перегрузка | «Тихо в темноте» |

Маппинг вынесен в данные (`PracticeCatalog`), чтобы менять без правки экранов.

## 11. Тон микрокопи (обязательно для всех строк)

**Разрешающий тон везде:** «можно», «если будет удобно», «необязательно
сейчас», «без правильных ответов». **Никогда:** «вы должны», «не сдавайтесь»,
«вернитесь», «вы пропустили». Все ошибки — мягкие, не алармовые. Ни одного
восклицательного знака в служебных текстах.

## 12. Анти-паттерны (запрещено реализовывать)

Стрики, серии, бейджи, уровни, «вы пропустили», конфетти, рейтинги звёздами,
соцфункции, шеринг-провокации, автовоспроизведение следующего трека, тревожные
пуши, обратный отсчёт в пейволле, любые тёмные паттерны. Проверяется в QA (DoD).
